1. What is Aura Notes?

Aura Notes is a personal daily journal and task manager. Think of it like a calendar where each day has:

  • A note — with a title, content, and tags (like a diary entry)
  • A to-do list — tasks you can add, check off, and delete

It also tracks your streak (consecutive days of activity) and shows a GitHub-like contribution chart on a dashboard.

Key Features

  • 📅 Calendar view — click any day to write a note or add tasks
  • 📝 Rich daily notes with auto-save (saves 1 second after you stop typing)
  • ✅ Per-day to-do lists with progress tracking
  • 📊 Dashboard with activity heatmap and stats
  • 🔐 User accounts — register/login so your data syncs across devices
  • 🌙 Dark/light theme toggle
  • 🔥 Daily streak counter
Why a backend? Previously, everything was stored in the browser's localStorage — meaning data was stuck on one device. Now with the backend, your notes and tasks are saved in a database and accessible from anywhere you log in.

2. How the System Works

The app is split into two parts that talk to each other:

┌─────────────────────────────────────────────────────────────────┐ │ YOUR BROWSER │ │ │ │ ┌─────────────┐ ┌──────────────┐ ┌───────────────────┐ │ │ │ AuthPage │ │ Calendar │ │ DayWorkspace │ │ │ │ (Login/ │ │ (pick a │ │ (write note, │ │ │ │ Signup) │ │ day) │ │ add tasks) │ │ │ └──────┬───── │ └──────┬───────┘ └────────┬──────────┘ │ │ │ │ │ │ │ │ ▼ │ ▼ ▼ │ │ ┌──────────────────────────────────────────────────────────┐ │ │ │ useStore (React Hook) │ │ │ │ Manages all state + calls API for persistence │ │ │ └───────────────────────┬──────────────────────────────────┘ │ │ │ │ │ ▼ │ │ ┌──────────────────────────────────────────────────────────┐ │ │ │ api.js (API Client) │ │ │ │ Makes HTTP requests with JWT token attached │ │ │ └───────────────────────┬──────────────────────────────────┘ │ │ │ │ └───────────────────────────┼─────────────────────────────────────┘ │ HTTP requests (fetch) │ with Authorization: Bearer <token> ▼ ┌───────────────────────────────────────────────────────────────────┐ │ EXPRESS SERVER (port 3001) │ │ │ │ ┌────────────┐ ┌─────────────┐ ┌────────────────────────┐ │ │ │ Auth Routes │ │ Notes Routes│ │ Todos Routes │ │ │ │ /api/auth/* │ │ /api/notes/*│ │ /api/todos/* │ │ │ └──────┬─────┘ └──────┬──────┘ └───────────┬────────────┘ │ │ │ │ │ │ │ ▼ ▼ ▼ │ │ ┌──────────────────────────────────────────────────────────┐ │ │ │ SQLite Database (data.db) │ │ │ │ users | notes | todos │ │ │ └──────────────────────────────────────────────────────────┘ │ └───────────────────────────────────────────────────────────────────┘

In plain English:

  1. You open the app in a browser → it loads the React frontend
  2. You log in → the frontend sends your email/password to the Express server
  3. The server checks the database, and if correct, sends back a JWT token
  4. The frontend stores this token and includes it in every request from now on
  5. When you write a note or add a task, the frontend instantly updates the UI (optimistic update) and also sends the data to the server to save it in SQLite
  6. Next time you open the app (even on another device), it loads your data from the server

4. Backend — Server, Database & API

4.1 Server Entry Point

The server is a simple Express.js app. It listens on port 3001 and sets up three groups of routes:

server/index.js 
import express from 'express';
import cors from 'cors';
import authRoutes from './routes/auth.js';
import notesRoutes from './routes/notes.js';
import todosRoutes from './routes/todos.js';

const app = express();

app.use(cors());             // Allow cross-origin requests
app.use(express.json());    // Parse JSON request bodies

app.use('/api/auth', authRoutes);    // Login, register, verify
app.use('/api/notes', notesRoutes);  // Notes CRUD
app.use('/api/todos', todosRoutes);  // Todos CRUD

app.listen(3001);

Why SQLite? It's a file-based database — no need to install PostgreSQL or MySQL. The entire database is one file (data.db). Perfect for personal projects. If you ever need to scale, the SQL is standard and can be migrated easily.

5. Authentication System

The auth system uses JWT (JSON Web Tokens) — a standard way to handle stateless authentication.

5.1 How It Works

SIGNUP / LOGIN FLOW: ┌──────────┐ POST {email, password} ┌──────────┐ check DB ┌────────┐ │ Browser │ ─────────────────────────► │ Server │ ──────────► │ SQLite │ │ │ │ │ ◄────────── │ │ │ │ ◄─────────────────────── │ │ user data │ │ │ Stores │ { user, token } │ Creates │ └────────┘ │ token in │ │ JWT │ │ localStorage └──────────┘ └──────────┘ SUBSEQUENT REQUESTS: ┌──────────┐ GET /api/notes ┌──────────┐ │ Browser │ Authorization: │ Server │ │ │ Bearer eyJhbGc... ────► │ │ │ │ │ Verify │ ── valid? ──► return data │ │ ◄──── notes data ──────── │ JWT │ ── invalid? ► 403 error └──────────┘ └──────────┘

5.2 JWT Middleware

Every request to /api/notes and /api/todos goes through the authenticateToken middleware. It checks the token and attaches the user info to the request:

server/middleware/auth.js 
export function authenticateToken(req, res, next) {
  const authHeader = req.headers['authorization'];
  const token = authHeader && authHeader.split(' ')[1]; // "Bearer TOKEN" → "TOKEN"

  if (!token) return res.status(401).json({ error: 'Authentication required' });

  try {
    const decoded = jwt.verify(token, JWT_SECRET);
    req.user = decoded;  // { id, email, username }
    next();               // Continue to the route handler
  } catch {
    return res.status(403).json({ error: 'Invalid or expired token' });
  }
}

5.3 Password Security

Passwords are never stored in plain text. They are hashed using bcrypt with 10 salt rounds:

// During registration:
const passwordHash = bcrypt.hashSync(password, 10);

// During login:
const valid = bcrypt.compareSync(password, user.password_hash);

5.4 Token Expiry

Tokens expire after 30 days. When a token expires, the frontend detects the 401/403 response, clears storage, and shows the login page.

function App() {

7.3 AuthContext — Managing Login State

This React Context holds the current user and provides login/register/logout functions to any component:

src/contexts/AuthContext.jsx — simplified 
const login = async (email, password) => {
  const data = await api.login(email, password);
  localStorage.setItem('aura-token', data.token);   // Save token
  localStorage.setItem('aura-user', JSON.stringify(data.user));
  setUser(data.user);                              // Update state
};

const logout = () => {
  localStorage.removeItem('aura-token');
  localStorage.removeItem('aura-user');
  setUser(null);  // This triggers the app to show login page
};

7.4 useStore — The Data Store

This is the heart of the data layer. It's a custom React hook that:

  1. Loads all notes & todos from the server on mount
  2. Provides getter functions (getNote, getTodos)
  3. Provides action functions that do optimistic updates
What is an "optimistic update"? When you save a note, the UI updates immediately (so it feels instant), and the API call happens in the background. If the API call fails, the error is logged but the UI stays responsive.
src/hooks/useStore.js — optimistic save example 
const saveNote = useCallback((date, noteData) => {
  const key = getDateKey(date);

  // 1. Update UI immediately
  setNotes(prev => ({ ...prev, [key]: noteData }));

  // 2. Save to server in background
  api.saveNote(key, noteData).catch(err => {
    console.error('Failed to save note:', err);
  });
}, []);

7.5 API Client

All HTTP requests go through a central request() function that automatically attaches the JWT token:

src/lib/api.js 
async function request(url, options = {}) {
  const token = localStorage.getItem('aura-token');
  const headers = {
    'Content-Type': 'application/json',
    ...(token ? { Authorization: `Bearer ${token}` } : {}),
  };

  const res = await fetch(`/api${url}`, { ...options, headers });

  // If token expired, clear everything and reload
  if (res.status === 401 || res.status === 403) {
    localStorage.removeItem('aura-token');
    window.location.reload();
  }

  return await res.json();
}

9. How to Run the Project

Prerequisites

  • Node.js v18+ installed
  • npm (comes with Node.js)

Quick Start

# 1. Install all dependencies
npm install

# 2. Start both backend + frontend
npm run dev:all

This starts:

  • Express server on http://localhost:3001
  • Vite dev server on http://localhost:5173 (open this in browser)

Individual Commands

CommandWhat it does
npm run serverStart only the backend (port 3001)
npm run devStart only the frontend (port 5173)
npm run dev:allStart both together (recommended)
npm run buildBuild frontend for production
How does the frontend talk to the backend? During development, the Vite dev server proxies any request starting with /api to http://localhost:3001. This is configured in vite.config.js. So when the frontend calls fetch('/api/notes'), Vite forwards it to the Express server.

Vite Proxy Config

vite.config.js 
export default defineConfig({
  plugins: [react(), tailwindcss()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:3001',
        changeOrigin: true,
      }
    }
  }
});
